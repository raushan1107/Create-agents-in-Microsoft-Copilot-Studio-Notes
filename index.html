Ch 1The Quest Begins — "Is That Still the Current Module?"

Raushan had just told a batch that a particular Applied Skills credential was the way to certify PL-7008 skills — and a student messaged an hour later: "Sir, it says 'retired' on the page." Raushan checked. It was.

He realized his notes, his memory, even his own last-year screenshots could go stale — but Microsoft Learn itself never lies about its own current state. "I don't need to remember every module name and URL," he told himself. "I need a companion that always checks the source for me."

Before touching the tool, he reminded himself what Power Platform actually is: Copilot Studio for building the agent, Power Automate for the "doing" part, Dataverse as the table where the agent's index lives. Nothing to install — just a browser and a plan.

Ch 2Giving Birth to an Agent

Raushan opens Copilot Studio and selects Create.

🧠 "Let's call it the PL-7008 MS Learn Companion," he decided.

🛠️ He sets:

  • Name: PL-7008 MS Learn Companion
  • Description: Helps learners quickly find and verify the current official Microsoft Learn content for PL-7008 — modules, learning paths, docs, and credentials
  • Instructions: Only answer using content that traces back to a real learn.microsoft.com page. Always name the page and link it. If nothing on Learn matches, say so — never guess.
Create an agent called PL-7008 MS Learn Companion that helps learners find and verify current Microsoft Copilot Studio training content directly on learn.microsoft.com — modules, learning paths, product docs, and credentials. The agent should always cite the specific Microsoft Learn page it used, and should say clearly when it can't find a matching page rather than guessing.

📌 This is where Raushan defines the agent fundamentals — and, importantly, a ground rule: this agent's job is to point outward to the real platform, never to answer from its own assumptions.

Concept: Agent identity, description, instructions

Ch 3Teaching the Bot to Think

"A companion that checks the source is only as good as the index it checks against," Raushan reminded himself.

He enables:

  • ✅ Generative AI — so it can answer open-ended questions
  • ✅ Knowledge source — a "PL-7008 MS Learn Reference" doc Raushan maintains: the real learning-path and module URLs for Copilot Studio, kept current, each with a one-line description

🧪 Demo try: Raushan typed in the test panel — "Which module covers entities and variables?" The Companion answered with the actual module title and a direct learn.microsoft.com link, pulled straight from the reference doc.

💡 TipGenerative AI lets the agent answer questions even when no topic has been built for them. A well-maintained knowledge source is what keeps every one of those answers traceable back to a real Microsoft Learn page instead of a plausible-sounding guess.

Ch 4Let's Talk Topics

With the knowledge source in place, Raushan structures the one conversation that needs a safety net: what happens when the Companion genuinely can't find a match.

Raushan realized: "If it can't verify something, it should say so and hand off — never bluff." Topics are where he builds that guardrail.

💬 He learns: a Topic = Trigger + Flow (questions, responses, actions), and there are system topics too, like Greeting and Fallback.

🛠️ He creates a topic: "Ask Raushan directly" —

  • Trigger phrases: "I don't think that's right", "can you double-check that", "that page doesn't exist"
  • A question node collects what the learner was trying to verify
  • A message node responds honestly, confirming it will be checked and corrected
Create a topic called "Ask Raushan directly" that triggers when a learner says things like "I don't think that's right", "can you double-check that", or "that page doesn't exist". The topic should ask what they were trying to verify, then show a message confirming it will be reviewed and the reference doc corrected if needed.

📌 Raushan now understands topic design, trigger phrases, and flow control — applied to something that matters more than convenience: not being wrong with confidence.

Concept: Topics, triggers, question & message nodes

Ch 5Smart Conversations with Conditions & Cards

Building on the basic topic, Raushan wants the Companion to handle a real lookup request cleanly.

"What if someone asks for a 'Module' but really means a whole 'Learning Path'? The right answer looks different each time."

He builds "Find it on MS Learn" and adds a condition node:

  • If the resource type doesn't match a known value → ask again instead of failing silently
  • If it matches → move on to the lookup

Then he formats the response as a citation-style card: the page title, its type (Module / Learning Path / Doc / Credential), and the live learn.microsoft.com link — never just a bare chat sentence.

Edit the "Find it on MS Learn" topic to add a condition: if the learner doesn't provide a valid resource type from the ResourceType entity, ask them to choose from the list again instead of failing silently. Show matching results as a card with the page title, resource type, and the learn.microsoft.com link.

📌 He learns about condition nodes, and how presenting an answer as a citation — not just prose — is what makes "check the source" actually mean something.

Ch 6Making the Bot Learn: NLU & Training

"People won't all phrase a fact-check the same way," Raushan realized.

He improves trigger phrases and trains the Companion:

  • Adds variants like "check this on MS Learn", "is there an official module for this", "verify against Microsoft Learn"
  • Sets priority so "Find it on MS Learn" wins over the generic FAQ answer when a learner clearly wants a citation
  • Uses debug mode to see exactly which topic fired and why
💡 TipDebug mode is the fastest way to find out why a topic didn't trigger — it shows you the recognized intent, not just the final answer.

Ch 7Knowing More: Variables and Entities

To make the Companion genuinely useful, Raushan needs it to recognize exactly what kind of Microsoft Learn resource someone is after.

He:

  • Creates a custom entity: LearnTopicArea (Agent Fundamentals, Topics, Entities & Variables, Automation, Autonomous Agents, Publishing) — mirroring PL-7008's own module structure
  • Creates a second custom entity: ResourceType (Learning Path, Module, Product Doc, Applied Skills, Credential)
  • Stores captured values in variables like learnTopicArea and resourceType
Create a custom entity called LearnTopicArea that recognizes Agent Fundamentals, Topics, Entities and Variables, Automation, Autonomous Agents, and Publishing, matching the module structure of PL-7008. Then create a second entity called ResourceType that recognizes Learning Path, Module, Product Doc, Applied Skills, and Credential.

🧠 "Now my Companion can pin down exactly what someone needs before it goes looking," Raushan smiled.

Ch 8Automation: Checking Against the Real Source

Having set up understanding and memory, Raushan now wants the agent to perform the actual check, not just describe how it would.

"It's time for the Companion to look something up for real."

Raushan builds an agent flow / Power Automate tool that:

  • Takes the captured LearnTopicArea and ResourceType
  • Queries an MS Learn Resource Index Dataverse table Raushan maintains — Title, ResourceType, LearnTopicArea, URL, LastVerified — each row a real learn.microsoft.com page
  • Returns up to three matching resources with their live links and the date Raushan last verified them

He connects this into his topic using a Call an Action node.

Add a tool that looks up official Microsoft Learn resources in the MS Learn Resource Index table, matching a given topic area and resource type, and returns up to three matching titles with their learn.microsoft.com links and last-verified dates.

📌 Now the Companion doesn't just describe Microsoft Learn from memory — it checks a maintained, real index and hands back a live citation, exactly the discipline Raushan already applies when he verifies his own tools before publishing them.

💡 TipKeeping a maintained index table (rather than trying to scrape Learn pages live) is the practical pattern here — it's the same idea as checking your own skill descriptions before you publish them: someone still has to keep the source of truth honest.

Ch 9Testing the Bot Like a Pro

Before trusting it in front of a batch, Raushan needs to know the Companion is actually accurate.

He opens the Test panel and:

  • Simulates several different learner questions
  • Enables track topics, to watch which one fires and why
  • Checks captured variable values after each question
  • Deliberately tests edge cases — an unclear resource type, a topic area with no indexed match, an outdated URL

Ch 10Time to Shine: Deployment

With a thoroughly tested Companion, Raushan is ready to share it.

🛠️ He:

  • Selects Publish
  • Generates a demo website link for quick sharing
  • Deploys the agent to Microsoft Teams so students can ask it mid-class
  • As a stretch capability, adds an Outlook trigger so the Companion can reply to a "Check on MS Learn" email autonomously — no live chat needed

🎉 Students now get an answer that always traces back to a real learn.microsoft.com page — any hour, no need to trust anyone's memory, including Raushan's own.

💡 TipTesting in the Test panel and testing a published, live trigger are genuinely different — always publish before you expect a real-world trigger (like an incoming email) to fire.
